## Figure 1: 核心结论概览

### 客观描述（5A）

三面板折线图（对数坐标），展示三种方法预测的最优模型大小和训练 token 数：
- 左：Loss vs FLOPs（三种方法的预测叠加）
- 中/右：最优参数量和最优 token 数随 FLOPs 预算的变化
- 绿色标注：Gopher 的计算预算对应的最优点
- 对比：Kaplan et al. (2020) 的预测（模型应该更大，数据可以更少）

### 深度分析（5B）

- **独立解读**：三种方法（Approach 1/2/3）的预测高度一致——都指向"模型应该更小，数据应该更多"。而 Kaplan 的预测（虚线）明显偏向更大的模型。Gopher 用了 280B 参数 + 300B tokens，但最优点指向 70B 参数 + 1.4T tokens。
- **验证的假设**：这是论文的核心论据图——三种独立方法得到一致结论，增强说服力。
- **批判**：三种方法都基于相同的实验数据（400+ 模型），只是分析角度不同。如果实验数据有系统性偏差（如模型架构限制），三种方法会共享同一个偏差。
- **面试价值**：面试中如果问"Chinchilla 的核心发现"，这张图就是答案——三种方法一致预测最优 scaling 是 N∝C^0.5, D∝C^0.5。

## Figure 2: Approach 1 — Training Curve Envelope

### 客观描述（5A）

三面板图：
- 左：所有训练曲线（不同模型大小 × 不同训练长度），展示 loss 随 FLOPs 的变化
- 中：从 envelope 中提取的最优模型大小 vs FLOPs → 拟合幂律 N_opt ∝ C^0.50
- 右：最优训练 token 数 vs FLOPs → 拟合幂律 D_opt ∝ C^0.50

### 深度分析（5B）

- **独立解读**：
  - 左图中，每条曲线是同一模型在不同训练步数的 loss。envelope（包络线）连接了每个 FLOP 预算下的最低 loss
  - 中图：最优参数量随计算预算的 0.50 次方增长
  - 右图：最优 token 数也随计算预算的 0.50 次方增长
  - **a = 0.50, b = 0.50** → 模型大小和训练数据应该**等比例增长**

- **验证的假设**：这是论文最核心的定量发现。Kaplan 的 a=0.73, b=0.27 意味着"优先增大模型"，而 Chinchilla 的 a=0.50, b=0.50 意味着"模型和数据同等重要"。

- **批判**：
  1. 所有模型最大到 16B——从 16B 外推到 70B 或 280B 是巨大的跳跃
  2. 幂律拟合假设关系是纯幂律——如果有曲率（论文 Appendix E 承认有轻微曲率），外推会有误差
  3. 实验用的是和 Gopher 相同的架构——对其他架构（如 MoE）是否适用未知

- **面试价值**：面试中问"scaling laws 说模型和数据应该怎么 scale"，答案是 N∝C^0.5, D∝C^0.5——模型和数据等比例增长。

## Figure 3: Approach 2 — IsoFLOP Profiles

### 客观描述（5A）

三面板图：
- 左：9 个固定 FLOP 预算下，loss 随模型大小的变化（每个 FLOP 预算一条抛物线）
- 中/右：从抛物线最低点提取的最优参数量和 token 数

### 深度分析（5B）

- **独立解读**：左图每条曲线都有清晰的"U 形"——模型太小 underfitting，模型太大 overfitting（因为固定 FLOP 下更大模型只能看更少数据）。最低点就是该 FLOP 预算下的最优大小。
- **关键发现**：a=0.49, b=0.51——和 Approach 1 的 a=0.50, b=0.50 几乎一样。两种独立方法得到一致结论。
- **面试价值**：IsoFLOP 是最直观的方法——固定计算预算，找到 loss 最低的模型大小。U 形曲线说明"太大太小都不好"。

## Table 1: 当前大模型对比

### 客观描述（5A）

| 模型 | 参数量 | 训练 tokens |
|------|--------|-----------|
| LaMDA | 137B | 168B |
| GPT-3 | 175B | 300B |
| Jurassic | 178B | 300B |
| Gopher | 280B | 300B |
| MT-NLG | 530B | 270B |
| **Chinchilla** | **70B** | **1.4T** |

### 深度分析（5B）

- **核心对比**：所有模型都用了 ~300B tokens，而 Chinchilla 用了 **1.4T**（4.7x 更多）但只有 **70B** 参数（4x 更小）。
- **验证的假设**：这张表直接展示了论文的核心论点——当前大模型都 undertrained。Gopher 280B 只用了 300B tokens，而计算最优需要 1.4T。
- **批判**：后来的 LLaMA 系列验证了这个发现——LLaMA-1 65B 用了 1.4T tokens，效果接近 GPT-3 175B。
- **面试价值**：面试中问"为什么 Chinchilla 比 Gopher 好"，答案：用了 4x 更多数据但 4x 更小的模型——计算量一样但分配方式不同。

## Table 2: 三种方法的指数对比

### 客观描述（5A）

| 方法 | a (参数指数) | b (数据指数) |
|------|------------|------------|
| Kaplan et al. | 0.73 | 0.27 |
| **Approach 1** | **0.50** | **0.50** |
| **Approach 2** | **0.49** | **0.51** |
| **Approach 3** | **0.51** | **0.49** |

### 深度分析（5B）

- **核心发现**：三种方法的 a 和 b 都接近 0.5。而 Kaplan 的 a=0.73, b=0.27。
- **为什么 Kaplan 的结论不同？** 论文指出两个方法学问题：
  1. Kaplan 对所有模型用了**固定的学习率 schedule 长度**（130B tokens），导致短训练的模型被不公平地评估
  2. Kaplan 的大部分实验用了**很小的模型**（<100M），外推到大模型时曲率被忽略
- **面试价值**：面试中问"Chinchilla 和 Kaplan 的 scaling laws 有什么不同"，答案：Kaplan 说优先增大模型（a=0.73），Chinchilla 说模型和数据等比例增长（a=0.50）。

## Figure 4: Chinchilla vs Gopher 及其他大模型

### 客观描述（5A）

柱状图，展示 Chinchilla（70B/1.4T）vs Gopher（280B/300B）vs 其他大模型在多个 benchmark 上的性能。

### 深度分析（5B）

- **独立解读**：Chinchilla 在几乎所有任务上都优于 Gopher——尽管参数量只有 1/4。
- **MMLU（最综合的 benchmark）**：Chinchilla 67.5% vs Gopher 60.0%——**提升 7.5%**。这甚至超越了 GPT-3（175B）和 MT-NLG（530B）。
- **验证的假设**：直接验证了"计算最优 = 更小模型 + 更多数据"的论点。计算量一样，但分配方式不同导致 Chinchilla 全面超越 Gopher。
- **批判**：Chinchilla 用了 1.4T tokens 的数据——这么多高质量数据从哪来？论文用了和 Gopher 相同的数据但**训练了多个 epoch**（~4 epochs）。多 epoch 训练是否会导致过拟合/记忆？论文没有深入讨论。
- **面试价值**：这是 Chinchilla 论文的"一图胜千言"——70B 参数的模型全面超越 280B/175B/530B 的模型，证明了数据量的重要性。
