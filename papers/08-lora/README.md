# 📖 LoRA: Low-Rank Adaptation of Large Language Models

> **论文**：Hu et al., 2021 (Microsoft) | ICLR 2022
>
> **一句话总结**：冻结预训练权重，注入低秩分解矩阵——用 0.01% 可训练参数达到全量微调效果，且推理零额外延迟。

---

# 第一层：鸟瞰

## 🎯 核心贡献

1. **低秩假设**：模型微调时权重变化 $\Delta W$ 具有"低内在秩"——用 $B \cdot A$（r ≪ d）近似即可
2. **参数效率**：GPT-3 175B 全量微调需要更新 175B 参数，LoRA 只需 ~18M（0.01%）
3. **零推理延迟**：部署时 $BA$ 可以合并到 $W_0$ 中——不增加任何推理计算
4. **模块化**：一个基础模型 + 多个小 LoRA 模块 = 多个任务适配器，切换成本低

## 📍 知识网络定位

```
Adapter Tuning (2019) → 插入小层但增加推理延迟
Prefix Tuning (2021) → 优化 prompt 但减少可用序列长度
         ↓
   【LoRA (2021.06)】→ 低秩分解，零推理延迟
         ↓
   QLoRA (2023.05) → LoRA + 4-bit 量化
   LoRA+ (2024) → 不对称初始化
   DoRA (2024) → 分解幅度和方向
```

# 第二层：精读

## 1. 问题定义

全量微调：$\max_\Phi \sum \log P_\Phi(y_t | x, y_{<t})$

每个任务需要学习 $\Delta\Phi$，其维度 $|\Delta\Phi| = |\Phi_0|$（GPT-3 = 175B）。

LoRA：将 $\Delta\Phi$ 编码为更小的参数集 $\Theta$，$|\Theta| \ll |\Phi_0|$。

## 2. 为什么现有方法不够好？

### Adapter Layers 的问题
- 增加推理延迟（即使参数 <1%，但需要顺序处理）
- 模型并行时更严重（额外的 AllReduce/Broadcast）

### Prefix Tuning 的问题
- 难优化，性能非单调
- 占用序列长度 → 减少可用上下文

## 3. LoRA 方法

### 核心公式

对预训练权重 $W_0 \in \mathbb{R}^{d \times k}$：

$$h = W_0 x + BAx$$

其中 $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$, $r \ll \min(d,k)$

- $W_0$：冻结，不更新
- $A$：随机高斯初始化
- $B$：零初始化（训练开始时 $\Delta W = BA = 0$）
- 可训练参数：$(d + k) \times r$（vs 全量微调的 $d \times k$）

### 参数量对比

GPT-3 的 $W_q$ 维度 12288×12288：
- 全量微调：$12288^2 \approx 150M$ 参数/层
- LoRA (r=8)：$(12288 + 12288) \times 8 \approx 197K$ 参数/层
- **压缩比 ~760x**

### 为什么 $B$ 初始化为零？

训练开始时 $\Delta W = B \cdot A = 0$（因为 $B=0$）→ 模型输出和预训练模型完全一样 → **不破坏预训练知识**。

### 缩放因子 $\alpha$

实际应用中加一个缩放：$\Delta W = \frac{\alpha}{r} BA$

- $\alpha$ 固定，$r$ 变化时不需要重新调学习率
- 实践中常用 $\alpha = 2r$ 或 $\alpha = 16$

### 应用到哪些层？

论文发现：
- 只对 $W_q$ 和 $W_v$ 用 LoRA 效果最好
- 对所有注意力矩阵（Q/K/V/O）用 LoRA 效果接近全量微调
- 对 MLP 层用 LoRA 提升不大

> ❓ **为什么 Q 和 V 最重要？** Q 控制关注什么，V 控制传递什么信息。微调主要改变"关注什么信息、传递什么信息"——这恰好是 Q 和 V 的功能。

### 推理零延迟

部署时：$W_{\text{deploy}} = W_0 + BA$（一次性合并）

合并后权重和原始权重完全一样——**不增加任何推理计算**。

> 💡 这是 LoRA 相比 Adapter 的核心优势——Adapter 在推理时需要额外的前向传播，LoRA 不需要。

## 4. 实验

### GPT-2 Medium

LoRA (r=4) 在 E2E NLG 挑战上匹配或超过全量微调。

### GPT-3 175B

| 方法 | 可训练参数 | WikiSQL 准确率 | MNLI 准确率 |
|------|-----------|--------------|------------|
| Full Fine-tuning | 175B | ~73% | ~89% |
| **LoRA (r=4)** | **~18M** | **~73%** | **~89%** |
| Adapter | ~18M | ~70% | ~87% |
| Prefix Tuning | ~18M | ~67% | ~85% |

> 💡 LoRA 用 0.01% 参数达到了全量微调的效果——且推理零延迟。

# 第三层：批判性思考

## 🤔 设计决策分析

### 低秩假设成立吗？

论文引用 Aghajanyan et al. (2020) 证明预训练模型有"低内在维度"。但微调时的 $\Delta W$ 是否也是低秩的？

> ❓ **实验证据**：r=1 或 r=2 在某些任务上就足够了（GPT-3 175B 的 $d=12288$）！这意味着微调只需要在一个极低维的子空间中移动权重。

### 为什么不用 MLP 做适配？

LoRA 用线性分解 $BA$ 而不是非线性 MLP。

> ❓ **原因**：线性的好处是**可以合并**到原始权重中（$W_0 + BA$），推理零延迟。非线性无法这样做。但这也限制了 LoRA 的表达能力——后来 DoRA 通过分解幅度和方向来增强。

### LoRA 的局限

1. **容量有限**：低秩意味着表达能力受限——复杂任务可能需要更大的 r
2. **任务干扰**：多个 LoRA 模块合并时可能互相干扰
3. **和 RLHF 的兼容性**：LoRA 主要用于监督微调，RLHF 的 PPO 阶段通常需要全量微调

## 🎯 面试视角

**Q1: LoRA 的核心思想？**

> A: 预训练权重 $W_0$ 冻结，用低秩分解 $BA$（$r \ll d$）近似权重变化 $\Delta W$。只训练 A 和 B，参数量减少 ~760x，部署时合并到原始权重，推理零延迟。

**Q2: 为什么推理零延迟？**

> A: 因为 $W_0 + BA$ 可以预先计算合并为一个矩阵。推理时只做一次矩阵乘法，和原始模型完全一样。这是 LoRA 相比 Adapter 的核心优势。

**Q3: r（秩）怎么选？**

> A: 论文发现 r=4-8 在大多数任务上就足够了。r 越大容量越大但参数越多。实践中的经验：简单任务 r=4，复杂任务 r=16-64。也可以用 r=1-2 在极端参数效率场景。

**Q4: LoRA 和 QLoRA 的区别？**

> A: QLoRA = LoRA + 4-bit 量化基础模型。基础模型量化到 4-bit（节省显存），LoRA 适配器保持 fp16/bf16。进一步降低了微调门槛——65B 模型可以在单卡 48GB GPU 上微调。

**Q5: LoRA 对大模型生态的影响？**

> A: LoRA 使得"一个基础模型 + 多个小适配器"成为可能——极大地降低了部署成本。后来成为开源社区的标准微调方式（Stable Diffusion、LLaMA 等都用 LoRA 微调）。
