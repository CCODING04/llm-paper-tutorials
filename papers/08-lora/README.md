# 📖 LoRA: Low-Rank Adaptation of Large Language Models

> **论文**：Hu et al., 2021 (Microsoft) | ICLR 2022
>
> **一句话总结**：冻结预训练权重，注入低秩分解矩阵 B·A——用 0.01% 可训练参数达到全量微调效果，且推理零额外延迟。

---

# 第一层：鸟瞰

## 🎯 核心贡献

1. **低秩假设的系统验证**：微调时权重变化 ΔW 确实是低秩的——r=1~2 在某些任务就够（GPT-3 的 d=12288）
2. **参数效率**：GPT-3 175B 全量微调 175B 参数，LoRA 只需 ~18M（0.01%）——**10,000 倍减少**
3. **零推理延迟**：部署时 B·A 合并到 W₀ → 不增加任何推理计算
4. **模块化**：一个基础模型 + 多个小 LoRA 模块 = 多任务适配器，切换成本极低
5. **消融实验深入**：哪些权重矩阵加 LoRA？rank 怎么选？子空间相似性分析——不只是方法，还理解了"为什么"

## 📍 知识网络定位

```
Adapter Tuning (2019) → 插入小层但增加推理延迟
Prefix Tuning (2021) → 优化 prompt 但减少序列长度
BitFit (2021) → 只训练 bias 参数
         ↓
   【LoRA (2021.06)】→ 低秩分解，零推理延迟
         ↓
   QLoRA (2023.05) → LoRA + 4-bit 量化
   LoRA+ (2024) → 不对称初始化
   DoRA (2024) → 分解幅度和方向
   rsLoRA (2023) → rank-stabilized scaling
```

# 第二层：精读

## 1. 引言：为什么需要参数高效微调？

### 全量微调的问题

GPT-3 175B 全量微调 = 每个任务 175B 参数的副本。10 个任务 = 1.75T 参数。

> ❓ **为什么不直接全量微调？** (1) 存储：每个任务存一份 700GB 模型；(2) 部署：切换任务需要加载不同模型；(3) 训练：需要为 175B 参数维护优化器状态（Adam 需要 2x 参数量的额外显存）。

### 现有方法的局限

| 方法 | 问题 |
|------|------|
| Adapter Layers | 增加推理延迟（顺序处理，不能并行） |
| Prefix Tuning | 难优化 + 占用序列长度 |
| BitFit | 只训 bias，容量太小 |

## 2. 方法：LoRA

### 2.1 核心公式

对预训练权重 $W_0 \in \mathbb{R}^{d \times k}$：

$$h = W_0 x + \Delta W x = W_0 x + B A x$$

其中 $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$, $r \ll \min(d, k)$

**关键设计**：
- **$W_0$ 冻结**：不更新
- **$A$ 随机高斯初始化**
- **$B$ 零初始化**：训练开始时 $\Delta W = BA = 0$ → 不破坏预训练知识
- **缩放因子**：$\Delta W = \frac{\alpha}{r} BA$（固定 α，变 r 不用调学习率）

> ❓ **为什么 B 零初始化？** 如果 B 也随机初始化，训练开始时 ΔW ≠ 0 → 模型输出和预训练模型不同 → 破坏预训练知识。B=0 保证了"从预训练模型出发"的起点。

### 2.2 参数量对比

GPT-3 的 $W_q$ (12288 × 12288)：
- 全量微调：$12288^2 = 150,994,944$ 参数/层
- LoRA (r=8)：$(12288 + 12288) \times 8 = 196,608$ 参数/层
- **压缩比 ~768x**

96 层 × 只对 Q 和 V 加 LoRA：
- 全量微调：96 × 150M × 4 (Q/K/V/O) ≈ 57.6B（只注意力层）
- LoRA (r=8)：96 × 196K × 2 (Q+V) ≈ 37.7M
- **总压缩比 ~1500x**

### 2.3 推理零延迟

部署时一次性合并：$W_{\text{deploy}} = W_0 + BA$

合并后和原始权重完全一样——不增加任何推理计算。

> 💡 **这是 LoRA 相比 Adapter 的核心优势**。Adapter 在推理时需要额外的前向传播（即使参数 <1%），因为 adapter layers 必须顺序处理。LoRA 的 BA 可以预先合并。

## 3. 消融实验：深入理解 LoRA

### 3.1 哪些权重矩阵应该加 LoRA？

**实验**：在 GPT-3 上分别对 Q/K/V/O 加 LoRA，保持相同的可训练参数量

| 应用位置 | WikiSQL | MultiNLI |
|---------|---------|----------|
| $W_q$ only | 73.1 | 88.7 |
| $W_k$ only | 72.6 | 88.6 |
| $W_v$ only | 73.2 | 88.6 |
| $W_o$ only | 72.8 | 88.5 |
| $W_q + W_k$ | 73.4 | 88.8 |
| **$W_q + W_v$** | **73.8** | **89.2** |
| $W_q + W_k + W_v + W_o$ | 73.7 | 89.0 |

> 💡 **$W_q + W_v$ 效果最好！** 4 个矩阵全加反而略差（相同参数预算下每个的 rank 更小）。

> ❓ **为什么 Q 和 V 最重要？** Q 控制"关注什么"，V 控制"传递什么信息"。微调主要改变"关注什么信息、传递什么信息"——恰好是 Q 和 V 的功能。K（"被什么匹配"）的修改需求相对低。

### 3.2 Rank 怎么选？

**实验**：$W_q + W_v$ 方案，改变 r

| Rank r | WikiSQL | MultiNLI |
|--------|---------|----------|
| 1 | 73.5 | 89.0 |
| 2 | 73.6 | 89.1 |
| **4** | **73.8** | **89.2** |
| 8 | 73.7 | 89.1 |
| 64 | 73.7 | 89.2 |

> 💡 **r=1 就和 r=64 差不多！** 这说明微调确实只需要在一个极低维子空间中移动权重。

> ❓ **为什么 r=1 够用？** 微调不是重新学习——而是在预训练知识的基础上做小幅调整。这些调整落在一个极低维的子空间中。

### 3.3 子空间相似性分析

**实验**：对比 r=8 和 r=64 的 A 矩阵的列向量子空间

**发现**：r=8 的 top 方向包含在 r=64 的子空间中（反之亦然）→ 增加 r 只是增加了冗余方向，不增加有效信息。

**两个随机种子**的子空间相似性很低 → LoRA 学到的子空间是确定性的（不是随机的）。

> ❓ **这说明了什么？** 存在一个"最优低秩子空间"——无论 r=8 还是 r=64，模型都找到了同一个子空间。增加 r 只是增加了对这个子空间的冗余表示。

### 3.4 ΔW 和 W₀ 的关系

**实验**：计算 ΔW 的 top-r 奇异向量方向和 W₀ 的 top-r 奇异向量方向的重叠度

**发现**：ΔW 的方向和 W₀ 几乎正交 → LoRA 学到的是**新的**方向，而不是放大 W₀ 的已有方向。

> ❓ **为什么正交？** 因为预训练模型已经在 W₀ 的主要方向上做得很好了。微调需要的是"补充"新的、小的调整——这些调整在 W₀ 的正交补空间中。

## 4. GPT-3 175B 实验

### 核心结果

| 方法 | 可训练参数 | WikiSQL | MNLI |
|------|-----------|---------|------|
| Full Fine-tuning | 175B | 73.8% | 89.5% |
| **LoRA (r=4, Q+V)** | **~18M** | **73.8%** | **89.2%** |
| Adapter | ~18M | 72.2% | 88.3% |
| Prefix Tuning | ~18M | 69.7% | 87.5% |

> 💡 LoRA 用 0.01% 参数**匹配**全量微调——且推理零延迟。

### 推理延迟对比

| 方法 | Batch=32,Seq=512 | Batch=1,Seq=128 |
|------|-----------------|----------------|
| Fine-tune/LoRA | 1449ms | 19.8ms |
| Adapter^L | 1482 (+2.2%) | 23.9 (+20.7%) |
| Adapter^H | 1492 (+3.0%) | 25.8 (+30.3%) |

> 💡 在线推理（batch=1, short sequence）时 Adapter 延迟增加 30%——LoRA 完全零延迟。

# 第三层：批判性思考

## 🤔 设计决策分析

### 为什么用线性分解而不是非线性？

LoRA 用 $BA$（线性），不用 MLP（非线性）。

> ❓ **原因**：线性的好处是可以**合并**到原始权重中（$W_0 + BA$），推理零延迟。非线性无法这样做。但这也限制了表达能力——后来 DoRA 通过分离幅度和方向来增强。

### LoRA 的容量限制

r=4 在 GPT-3 上够用，但后来发现更大的模型或更复杂的任务需要 r=16-64。

> ❓ **什么时候 LoRA 不够？** (1) 复杂任务需要更多容量；(2) 多任务合并时可能互相干扰；(3) RLHF 的 PPO 阶段通常需要全量微调（或很大的 r）。

### 缩放因子 α/r 的选择

论文用 $\Delta W = \frac{\alpha}{r} BA$。实践中常用 α=16 或 α=2r。

> ❓ **为什么需要缩放？** 不同 r 下 LoRA 的"信号强度"不同——r 越大 BA 的范数越大。缩放因子让不同 r 的信号强度一致，方便调参。

## ⚠️ 局限性

1. **容量有限**：低秩 = 表达能力受限——复杂任务可能需要大 r
2. **任务干扰**：多个 LoRA 模块合并时可能互相干扰
3. **只验证了注意力层**：论文只对 Q/V/O 加 LoRA，MLP 层未充分探索
4. **和 RLHF 兼容性有限**：PPO 阶段通常需要全量微调
5. **理论支撑弱**：为什么微调的 ΔW 是低秩的？只有经验验证，没有理论证明

## 🎯 面试视角

**Q1: LoRA 的核心思想？**

> A: 预训练权重 W₀ 冻结，用低秩分解 BA（r≪d）近似权重变化 ΔW。只训练 A 和 B，参数量减少 ~768x。部署时合并 $W_0 + BA$，推理零延迟。

**Q2: 为什么推理零延迟？**

> A: $W_0 + BA$ 可以预先计算合并为一个矩阵。推理时只做一次矩阵乘法，和原始模型完全一样。这是 LoRA 相比 Adapter 的核心优势——Adapter 必须顺序处理额外层。

**Q3: r（秩）怎么选？为什么 r=1 就够？**

> A: 论文发现 r=4 在多数任务够用，r=1 在某些任务也行。因为微调的 ΔW 确实是低秩的——子空间分析证明存在"最优低秩子空间"，增加 r 只是冗余。实践中：简单任务 r=4-8，复杂任务 r=16-64。

**Q4: 为什么对 Q 和 V 加 LoRA 效果最好？**

> A: Q 控制"关注什么"，V 控制"传递什么"。微调主要改这两个——改变"关注什么信息、传递什么信息"。K 和 O 的修改需求相对低。有趣的是 4 个全加反而略差（因为相同参数预算下每个 rank 更小）。

**Q5: LoRA 和 QLoRA 的区别？后续发展？**

> A: QLoRA = LoRA + 4-bit 量化基础模型。基础模型量化到 4-bit（省显存），LoRA 保持 fp16/bf16。后续：LoRA+（不对称初始化）、DoRA（幅度+方向分离）、DORA（权重分解）。LoRA 成为开源微调标准（Stable Diffusion、LLaMA 等）。
