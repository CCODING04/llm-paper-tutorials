## Figure 1: LoRA 重参数化

### 客观描述（5A）

示意图：$W_0$（冻结，大矩阵）+ B·A（可训练，两个小矩阵）
- $W_0 \in \mathbb{R}^{d \times k}$（蓝色，冻结）
- $B \in \mathbb{R}^{d \times r}$（可训练，零初始化）
- $A \in \mathbb{R}^{r \times k}$（可训练，高斯初始化）
- 输出 $h = W_0 x + BAx$

### 深度分析（5B）

- **独立解读**：核心思想——大权重矩阵的变化可以用两个小矩阵的乘积近似
- **对照 caption**："Our reparametrization. We only train A and B." 简洁准确
- **验证的假设**：ΔW 是低秩的 → 可以用 BA 近似
- **批判**：图中没有展示缩放因子 α/r——这在实际应用中很重要
- **面试价值**：面试必考——画图解释 LoRA。B 零初始化保证不破坏预训练

## Table 1: 推理延迟对比

### 客观描述（5A）

GPT-2 Medium 推理延迟（ms，100 次平均，NVIDIA RTX8000）：

| 方法 | B=32,S=512 | B=1,S=128 |
|------|-----------|----------|
| Fine-tune/LoRA | 1449.4±0.8 | 19.8±2.7 |
| Adapter^L | 1482.0±1.0 (+2.2%) | 23.9±2.1 (+20.7%) |
| Adapter^H | 1492.2±1.0 (+3.0%) | 25.8±2.2 (+30.3%) |

### 深度分析（5B）

- **独立解读**：小 batch + 短序列时 Adapter 延迟增加 **30%**。大 batch 时只增加 2-3%。
- **为什么？** Adapter 层虽然参数少，但必须顺序处理。大 batch 时 GPU 并行度高，额外层的影响被摊薄。在线推理（batch=1）时 GPU 利用率低，额外层的影响被放大。
- **面试价值**：证明 LoRA 的"零延迟"优势在在线推理中尤其重要

## Table 2: 哪些权重矩阵加 LoRA？

### 客观描述（5A）

GPT-3 上不同 LoRA 应用位置的准确率（tex 验证）：

| 位置 | WikiSQL | MultiNLI |
|------|---------|----------|
| $W_q$ | 73.1 | 88.7 |
| $W_v$ | 73.2 | 88.6 |
| **$W_q + W_v$** | **73.8** | **89.2** |
| Q+K+V+O | 73.7 | 89.0 |

### 深度分析（5B）

- **核心发现**：Q+V 效果最好，比 4 个全加还好！因为相同参数预算下全加每个的 rank 更小
- **为什么 Q 和 V 最重要？** Q="关注什么"，V="传递什么"——微调主要改这两个
- **面试价值**：面试追问"LoRA 加在哪些层"的标准答案

## Table 3: Rank 选择

### 客观描述（5A）

| Rank r | WikiSQL ($W_q + W_v$) | MultiNLI |
|--------|----------------------|----------|
| 1 | 73.5 | 89.0 |
| **4** | **73.8** | **89.2** |

### 深度分析（5B）

- **r=1 和 r=64 差距只有 0.3%**——微调确实只需要极低秩
- 子空间分析（Figure 4/5）：r=8 的 top 方向 ⊂ r=64 的子空间 → 增加 r 是冗余
- **面试价值**："为什么 LoRA 有效"的答案——微调权重变化是低秩的

## Figure 4: 子空间相似性

### 客观描述（5A）

热力图：r=8 和 r=64 的 A 矩阵列向量子空间相似性

### 深度分析（5B）

- **核心发现**：r=8 的 top 方向包含在 r=64 中 → 存在一个"最优低秩子空间"
- **两个随机种子**的子空间相似性很低 → 学到的子空间是确定性的
- **面试价值**：解释"为什么 r=1 就够"——存在确定的最优子空间
