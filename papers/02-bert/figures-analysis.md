# BERT 论文图表分析

---

## Figure 1: BERT vs GPT vs ELMo 架构对比

### 客观描述（5A）

三张并排的架构示意图，从左到右分别是 BERT、OpenAI GPT、ELMo：

- **BERT**：多层蓝色椭圆（Trm）从下到上堆叠，每个 Trm 节点与上下**所有**其他 Trm 节点有双向箭头连接。输入 E₁-Eₙ（黄色），输出 T₁-Tₙ（绿色）。
- **GPT**：同样的 Trm 节点，但箭头**只指向左侧**（从左到右），每个位置只能看到前面的位置。
- **ELMo**：两组 LSTM——前向（左→右）和后向（右→左），两组独立运行后在输出层拼接。

### 深度分析（5B）

- **独立解读**：这是论文的"门面图"——用最直观的方式展示三种模型的核心差异：双向（全连接箭头）vs 单向（单向箭头）vs 浅层拼接（两套独立 LSTM）。
- **对照 caption**：caption 说 "Among three, only BERT representations are jointly conditioned on both left and right context in all layers"。与图一致——BERT 的箭头确实在每层都双向连接，ELMo 只在最终输出拼接。
- **验证的假设**：这张图本身不包含实验数据，但它是论文**核心论点的可视化**——双向性是关键创新。它为后续消融实验（Table 5）的论证做了铺垫。
- **批判性评价**：
  - 图的设计非常清晰，三种模型并排，变量控制得好（同样的输入输出形式）
  - 但有一个细微的"不公平"：BERT 和 GPT 是 fine-tuning 方式，ELMo 是 feature-based 方式——图的 caption 提到了这个区别但图本身没有体现
  - 没有展示"如果 GPT 也用 MLM 会怎样"的对比——后来确实有人做了这个实验（Table 5 的 LTR & No NSP 行）
- **面试价值**：面试中如果让你"画图对比 BERT 和 GPT"，这张图就是标准答案。核心差异用一句话概括：**BERT 每层都双向融合上下文，GPT 每层只能看左边。**

## Figure 2: BERT 输入表示

### 客观描述（5A）

一张示意图，展示 BERT 输入向量的构建方式。顶部是输入文本序列，下方是三个并行的嵌入层：

输入序列：`[CLS] my dog is cute [SEP] he likes play ##ing [SEP]`（共 11 个 token）

三个嵌入层（逐元素相加）：
1. **Token Embeddings**（绿色）：每个 token 对应一个向量，包括 E[CLS]、E_my、E_dog 等，子词用 `##` 标记（E_##ing）
2. **Segment Embeddings**（紫色）：句子 A 的 token 用 E_A，句子 B 的 token 用 E_B
3. **Position Embeddings**（灰色）：可学习的位置向量 E_0 到 E_10

三个嵌入逐元素相加得到最终输入向量。

### 深度分析（5B）

- **独立解读**：展示了 BERT 如何把文本转化为向量——三种信息（词义、句子归属、位置）叠加在一起。关键设计：[CLS] 在最开头，[SEP] 分隔两句，WordPiece 用 `##` 处理子词。
- **对照 caption**：caption 说 "The input embeddings is the sum of the token embeddings, the segmentation embeddings and the position embeddings"。与图一致。
- **验证的假设**：这张图说明 BERT 的输入设计能同时支持单句和句子对任务——Segment Embedding 是关键（E_A vs E_B）。这直接支持了论文"一个模型适配多种任务"的 claim。
- **批判性评价**：
  - 图非常清晰，三种嵌入用不同颜色区分
  - 值得注意的是：三种嵌入是**简单相加**而非拼接或更复杂的融合。后来的工作（如 T5）也用了相加，说明这个简单设计足够好
  - Position Embedding 用可学习参数而非正弦函数——图本身没体现这个区别
- **面试价值**：面试常问"BERT 的输入是怎么构建的"——这张图就是回答。三个要点：Token + Segment + Position 相加。

## Figure 3a: 句子对分类任务（MNLI, QQP 等）

### 客观描述（5A）

展示 BERT 微调到句子对分类任务的方式：
- 输入：Sentence 1 + [SEP] + Sentence 2
- 经过 BERT 编码后，取 [CLS] 的输出 C
- C 连接到一个分类层，输出 Class Label

### 深度分析（5B）

- **独立解读**：展示 BERT 最简单的下游适配方式——只需一个分类头。
- **验证的假设**：支持"预训练-微调"范式的简洁性 claim。
- **批判性评价**：看似简单但隐含一个假设——[CLS] 的表示足以区分句子对的关系。对于 MNLI（三分类：entailment/contradiction/neutral）来说，信息量是否足够？
- **面试价值**：面试中解释"BERT 怎么做分类"的标准答案——取 [CLS] 输出加一层 softmax。

### 客观描述（5A）

类似 3a 但只有单句输入，Segment Embedding 全部用 E_A。同样取 [CLS] 输出做分类。

### 深度分析（5B）

- **面试价值**：说明 BERT 的通用性——同一个模型，换输入格式就能做不同任务。

## Figure 3c: 问答任务（SQuAD）

### 客观描述（5A）

展示 BERT 微调到 SQuAD 问答任务的方式：
- 输入：Question + [SEP] + Paragraph
- 经过 BERT 编码后，每个 paragraph token 的输出 T_i 连接两个预测头
- **Start Span**：预测答案起始位置的概率分布
- **End Span**：预测答案结束位置的概率分布
- 红色箭头指向段落中被选中的起始和结束 token

### 深度分析（5B）

- **独立解读**：问答被转化为"在段落中找答案的起止位置"——不是生成答案，而是**抽取**答案。
- **验证的假设**：证明 BERT 的双向编码在问答任务上的优势——确定起始位置需要看后面的内容，确定结束位置需要看前面的内容。
- **批判性评价**：
  - 这个设计非常巧妙——把复杂的问答任务转化为两个简单的分类任务（起始位置分类 + 结束位置分类）
  - 但局限在于只能做**抽取式**问答——答案必须出现在原文中。无法做生成式问答。
  - 后来的 BART/T5 等模型解决了这个问题（用编码器-解码器架构生成答案）
- **面试价值**：面试高频问题——"BERT 怎么做 SQuAD？"答案：把问答转化为起止位置预测，两个向量（S 和 E）分别和每个 token 的输出做点积，softmax 后得到概率。

## Figure 3d: 序列标注任务（NER）

### 客观描述（5A）

展示 BERT 微调到 NER 任务的方式：
- 输入：单句
- 每个 token 的输出 T_i 直接连接分类头
- 输出每个 token 的标签（O 表示非实体，B-PER 表示人名实体开头等）

### 深度分析（5B）

- **独立解读**：每个 token 都需要分类——这是最直接的 token 级别任务。
- **验证的假设**：BERT 的双向编码在需要前后文信息的标注任务上有天然优势（判断"李"是否是人名，需要看后面是否跟着"明"或"华"等）。
- **批判性评价**：没有使用 CRF 层（条件随机场），这在传统 NER 中很常见。BERT 靠强大的表示能力弥补了这个简化。
- **面试价值**：BERT 做 NER 的方式比之前的 BiLSTM-CRF 简单得多——每个 token 直接分类，不需要序列建模层。

## Figure 4 / Table 5 相关图：训练步数消融

### 客观描述（5A）

折线图：
- 横轴：Pre-training Steps (Thousands)，范围 0-1000
- 纵轴：MNLI Dev Accuracy，范围 ~76-84
- 蓝色三角线：BERT_BASE (Masked LM)——从 ~78.6 上升到 ~84.4
- 红色叉号线：BERT_BASE (Left-to-Right)——从 ~79.4 上升到 ~82.2
- 两条线都在上升，蓝线始终在红线上方

### 深度分析（5B）

- **独立解读**：两个模型都在训练中持续进步，但 MLM（蓝色）始终优于 LTR（红色），且差距随训练步数有**扩大趋势**——说明双向优势不是暂时的，而是随着训练深入越来越大。另外，注意 LTR 在 30K 步时甚至略高于 MLM（79.4 vs 78.6），这可能因为 LTR 预测每个 token（信息密度更高），而 MLM 只预测 15%。
- **对照 caption**：caption 说 "ablation over number of training steps"，确认这是消融实验的一部分。
- **验证的假设**：这张图直接回答了"MLM 收敛更慢"的质疑——虽然早期稍慢，但很快追上并持续领先。更重要的是，即使给 LTR 无限训练时间，它也无法追上 MLM——因为**单向注意力本身就是信息瓶颈**。
- **批判性评价**：
  - 横轴只到 1000K 步，但论文说训练了 1M 步——两条线都还在上升，没有饱和。如果继续训练呢？
  - 纵轴范围 76-84，没有从零开始，可能稍微夸大了两条线的差异。但即使在同一个坐标系中，差距也是显著的
  - 只在 MNLI 上做了这个消融——不同任务上是否一致？
- **面试价值**：这是论文最有力的证据之一。面试中如果被问到"为什么 MLM 比 LTR 好"，这张图加上 Table 5 的消融数据就是最好的回答。
